# Branch sides of the ported Rust code that the tests comparing with the
# reference tables never take, with the reason. Checked by
# rust_branch_coverage.sh, which fails on any other untaken side and on
# any entry for a side that the tests take. Format:
# <file> <function> [<condition>] <true|false>: <reason>, where the
# condition is its source text with whitespace collapsed; an entry stands
# for every branch with the same file, function, condition and side.
#
# An out-of-range which has no Rust branch: there is one method per value
# of which (unreachable.txt lists the F90 lines).
#
# The Taylor series for P/R in gamma_inc (taylor_series_for_p_over_r,
# cdflib.f90:10827) never runs all 20 terms of its first loop: that needs
# the product of x/(a + k) for k = 1, ..., 20 above 1e-3, where the series
# has x <= max(a, 2.30) with a < 20 (big for iop = 1; it is smaller for the
# other accuracies) or x < 0.6 a; the largest value, at x = a near 20, is
# 3.1e-4. A sweep of 4.2 million (a, x) points, a from 0.5 to 2e4 in steps
# of 0.2 percent and x = a k/200 for k = 1, ..., 799, at the three
# accuracies, never ran all 20 terms. The end of a for loop is not a
# branch, so there is no entry for it.
